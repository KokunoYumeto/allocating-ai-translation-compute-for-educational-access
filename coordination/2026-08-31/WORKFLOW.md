# Recovery and coordination workflow

This document is a portable navigation aid, **not a replacement for the user's original instructions or a new workflow imposed on the language tasks**. Read those actual instructions and subsequent user direction in the originating project before resuming production. Private transcripts are intentionally not published here.

## Recover from durable evidence

Each task keeps an approximately 3,000-character goal (characters, not tokens), decisions, current coverage, source/canon locks and an exact next boundary outside the conversation. [CHECKPOINTS.json](CHECKPOINTS.json) locates these records. Persisting them supports restart after shutdown; it does not make a powered-off PC run.

Treat compaction summaries as untrusted navigation aids. Recheck consequential claims against the actual user messages, source witnesses, translation files, Git commits and QA receipts. Resolve stale prose against those artifacts and log the resolution. Never use a summary, an old "pilot complete" label or a test count to declare the entire assignment finished.

## Translate with readable canon in use

The user requested roughly 10–20 readable target-language canon examples to start, with focused additions when a new topic needs them. Consult the relevant examples during drafting, revision and QA; record the actual examples and decisions. Acquiring a corpus is not the same as using it. Do not loop indefinitely on acquisition or reading.

For PDFs, follow the user's instruction to OCR first so the material is readable, then actually consult that text and check it against the page as needed. Prefer accessible text, DOCX, Markdown or LaTeX where available. Preserve the distinction between language/register witnesses and mathematical authority. Where suitable canon does not exist, author the needed material transparently instead of inventing a citation or abandoning translation.

## Keep evidence and ownership explicit

Record source pin, module/section boundary, translated coverage, images/notation, original additions, decisions and outstanding checks. Preserve source omissions and disagreements with explicit provenance; separately label new answers. Reuse existing completed source/license audit results. Do not silently change the pinned original to make a discrepancy disappear.

Keep saved checkpoints separate from later working changes. Update a task's cursor after actual integration/review so another worker does not repeat completed work. Coordinate overlapping file ownership before editing. The original full-assignment goal remains active until the assigned materials and workflow are actually complete.

## Coordinator close-out is not translation completion

This coordinator packet can be finished while the nine translations continue. Issues may remain correctly assigned to a language, the user or a future integrator. No worker goal should be falsely completed to clear a stale control. The reported Indian Bengali/Javanese objective corrections require supported user controls; the [official long-running-work documentation](https://learn.chatgpt.com/docs/long-running-work) describes editing/resuming work through the goal progress row.

Respect actual access denials and approval boundaries. The recorded Marathi browser denial is a capability constraint, not permission to route the same inspection through another tool. Continue independent translation work and retain honest format-specific QA labels.
